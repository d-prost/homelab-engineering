# Incidents

Incident notes here are deliberately selective.

A public postmortem needs:

- a clear symptom;
- an understood root cause;
- a bounded correction;
- a reusable lesson;
- no live topology, credentials or recovery artifacts.

One-off debugging sessions and unresolved suspicions stay private.

The useful unit is not "something broke on Tuesday". It is "this failure mode was real, this is why it happened, and this is the guard that would catch it next time."
